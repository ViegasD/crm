# AUD02 — media ownership, binding and revocable browser access

Branch `codex/aud02-media-authorization` is stacked on AUD01 head `b5fcb07`. Integrate AUD01 first. Source publication does not deploy either branch or update the shared database.

## Implemented contract

- Migration `202611110002` adds `media_uploads`: workspace, uploader, storage key, canonical metadata, optional conversation binding and draft expiry. Upload requires workspace membership, an allowed MIME type, a safe filename and at most 25 MiB. Reads are capped; storage operations run in a thread pool.
- Unlinked uploads are owner-only for 24 hours. Ordinary message attachments must reference a registered upload; caller-provided URLs/buckets/names/sizes cannot authorize a file or change its canonical metadata. Binding locks the row, rejects another conversation and validates the complete batch before mutating bindings.
- `/media/presign` returns a relative `/api/v1/media/download?token=...` URL. Browser capabilities expire after five minutes and are scoped to the user and upload or message attachment. Every download rechecks current membership and conversation/template access, serves bytes through the app, and disables caching. The download route does not redirect to storage.
- Existing inbound/message attachments remain readable through authorized persisted messages. Their storage-key prefix is structural validation, not authorization. Unknown keys, foreign buckets and arbitrary external URLs are rejected.
- Saved canned/macro media remains reusable by authorized users across conversations and does not expire as an abandoned draft. Its persisted active workspace/sector/personal definition is the source of reusable access. New/updated definitions first validate file access, preserve canonical metadata and strip URLs. Existing-scope checks prevent changing an inaccessible sector template into a workspace grant; retained files are revalidated for reactivation/scope changes, even when attachments/actions are omitted from PATCH.
- Message, timeline and template output allowlists safe attachment metadata. Raw signed URLs, `sourceUrl`, nested provider payload/media keys and inline base64 are not exposed. Userless WebSocket serialization has no browser download capability. The media worker no longer stores signed download URLs.
- Providers receive a separate server-generated storage URL lasting 300 seconds after attachment authorization. Browser capabilities are not forwarded to providers. No real provider send was performed by the tests.
- A one-line `MessageOrigin.agent` → `MessageOrigin.crm_agent` correction removes the preexisting timeline crash so secure attachment output can be verified. Other AUD03 search/transfer work remains separate.

## Frontend and operations handoff

- Upload and presign still return `key`/`url`, but `url` is now relative to the app and carries a five-minute capability. The current gateway and Next `/api` rewrite support that path. Refresh a stale preview through authenticated `/media/presign`; send the key, not the preview URL, when posting a message. New safe attachment fields remain compatible with the client's camel-case conversion.
- Template lists expose safe keys/metadata, not permanent preview URLs. Thiago's media UI integration should request/refresh scoped previews when needed. External-URL-only legacy templates cannot safely authorize storage and must be reuploaded; legacy templates with valid workspace storage keys remain supported within their current scope.
- Apply the migration before starting the updated API, keep the storage bucket private, then run the updated deployment smoke through the app gateway. The smoke was updated for the new URL contract but has not been run against the shared app because this branch is not deployed.
- Already-issued historical storage URLs cannot be revoked retroactively and remain usable until their original expiry. Provider fetch URLs also remain bearer links until their 300-second expiry. Downloaded copies cannot be recalled. New browser capabilities reauthorize each request; they do not provide DRM.
- Draft expiry denies access and linking; this task does not physically purge abandoned objects or add storage lifecycle/retention jobs. Failed DB writes may leave inaccessible orphan objects for an operational cleanup policy. Agree that policy before production.
- AUD06 still owns durable/cross-process notifications. AUD05 still owns durable send correlation. No WhatsApp instance was paired, no customer messages were sent, and no frontend redesign was bundled into this backend change.
